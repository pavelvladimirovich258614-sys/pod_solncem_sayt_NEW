# Под Солнцем — туристическое агентство

Одностраничный сайт турагентства «Под Солнцем» (https://kupit-tyr.ru). Статический лендинг: посетитель смотрит направления и карточки туров, подбирает тур в виджете Tourvisor или пишет в офис по телефону и e-mail.

Сведения ниже проверены по коду в `origin/main` на коммите `7fd4df6`. Всё, что относится к серверу и внешним договорённостям, а не к коду, помечено отдельно.

## Структура

```
index.html        # весь сайт: HTML, CSS и JavaScript в одном файле
assets/images/    # 56 локальных WebP-изображений
assets/fonts/     # 15 локальных WOFF2-файлов (Onest, PT Serif, Caveat)
README.md         # этот файл
```

Числа получены подсчётом отслеживаемых файлов (`git ls-files assets/images | wc -l`, `git ls-files assets/fonts | wc -l`) и устаревают при любом добавлении файлов — пересчитывайте.

- Из 56 изображений страница использует 41. Ещё 15 лежат в репозитории и на сервере, но в `index.html` не упомянуты: прежние (без `-v2`) файлы наград, `manager.webp` и четыре старых `review-*.webp`. Они оставлены намеренно, удалять их без отдельного решения не нужно.
- Сборки, Node.js, npm, фреймворков и отдельных CSS/JS-файлов нет.
- Шрифты и изображения локальные: Google Fonts и сторонних хранилищ картинок страница не использует.
- Внешний виджет: Tourvisor, модуль `9965026` (`<div class="tv-search-form tv-moduleid-9965026">` и скрипт `//tourvisor.ru/module/init.js`). Найденные туры, цены, окно «Избранное» и его данные принадлежат Tourvisor, сайт их не редактирует.
- Кроме скрипта Tourvisor (и того, что подгружает сам виджет) страница сама не запрашивает внешние ресурсы. Внешние ссылки открываются по клику: Telegram-канал, WhatsApp и Telegram (контакт офиса) и документ политики на Яндекс.Диске.
- В опубликованном коде нет форм и обращений к серверной части (в `index.html` нет `<form>`, `fetch`, `XMLHttpRequest`, `sendBeacon`).

## Как открыть локально

1. Скачайте репозиторий (нужны `index.html` и папка `assets/`).
2. Запустите в папке сайта:

```bash
python -m http.server 8080
```

3. Откройте `http://localhost:8080`.

Если открыть `index.html` двойным кликом, картинки и шрифты подхватятся, но лучше проверять через локальный сервер. Виджет Tourvisor требует интернета; на `localhost` при проверках он работал под тестовым идентификатором клиента, а не боевым, поэтому итоговое поведение виджета надо смотреть на боевом домене.

- подбор туров через Tourvisor (блок `#tour-search`); под форму заранее зарезервирована высота, измеренная на боевом клиенте Tourvisor (`.tv-search-form{min-height}`: 205 px для широкой формы и 384 px для мобильной; мобильную форму Tourvisor показывает на сенсорных устройствах, кроме больших планшетов, маленький скрипт в `<head>` повторяет это условие и ставит класс `tv-mobile-form`), чтобы блоки ниже не сдвигались при загрузке виджета; резерв не снимается никогда: пока форма не отрисована, поверх него показывается статус «Загружаем форму подбора туров…», а если не загрузился сам скрипт Tourvisor — сообщение с кнопкой «Обновить страницу» и телефоном офиса;

- cookie-баннер и настройка согласий (`localStorage`, ключ `pod_solncem_cookie_consent`);

## Заявки с сайта: «Заказать звонок», «Напишите нам», «Круизы»

- **Что это.** Три кнопки открывают одно окно формы в трёх режимах: «Заказать звонок» (шапка от 768 px и мобильное меню: имя, телефон, согласие), «Напишите нам» (кнопка в баннере «Поможем найти ваше путешествие»: имя, телефон, обязательное сообщение, согласие) и «Круизы» (карточка в «Направлениях»: заголовок «Круизы», сообщение необязательно, в письме «ИНТЕРЕС: КРУИЗЫ»). Согласие со ссылками на текст согласия и политику, кнопка «Отправить заявку». Заявка уходит письмом на `coralclub5av@mail.ru`, почтовая программа посетителя не открывается. Состояния: проверка полей, «Отправляем…», «Заявка принята», ошибка с телефоном офиса.
- **Тексты окна.** Под заголовком «Заказать звонок» стоит «Оставьте имя и телефон — менеджер свяжется с вами.», без графика работы (замечание Сергея, 2026-10-06; на экране «Заявка принята» то же: «Менеджер перезвонит вам по указанному номеру.»). Под заголовком «Напишите нам»: «Расскажите, что вас интересует — менеджер уточнит детали и свяжется с вами.» (замечание Сергея, 2026-10-06); экран «Заявка принята» этого режима прежний: «Менеджер свяжется с вами по указанному номеру в рабочее время (Пн–Вс 10:00–22:00).» В режиме «Круизы» пояснение и экран успеха прежние, с графиком «в рабочее время (Пн–Вс 10:00–22:00)» (константа `HOURS` в скрипте окна). Тексты «Напишите нам» и «Круизы» заданы только в объекте `MODES` в конце `index.html`; у «Заказать звонок» они заданы дважды: в разметке окна и в `MODES`, менять нужно оба места.
- **Как устроено.** Страница статическая, форма отправляет `POST /api/callback` (JSON, поле `topic`: `callback`, `write` или `cruise`). nginx передаёт запрос сервису `kupit-tyr-lead` (`127.0.0.1:8731`, только loopback), сервис проверяет поля, защищается от спама и повторов и отправляет письмо напрямую на MX получателя. Код сервиса, тесты, юнит и блок nginx лежат в `server/callback/` (описание, лимиты и откат — `server/callback/README.md`). Эти файлы не входят в деплой `index.html`: их ставят на сервер отдельно.
- **Что подтверждено.** 2026-10-05 тестовые заявки («Заказать звонок» и «Круизы») приняты почтовым сервером `mxs.mail.ru` (SMTP 250, идентификатор сообщения в журнале сервиса `/var/log/kupit-tyr-lead/app.log`). Во «Входящие» письмо попало или в «Спам» — подтверждает только получатель. У домена `kupit-tyr.ru` нет SPF, DKIM и DMARC, у IP сервера нет PTR: почтовые провайдеры вправе отправлять такие письма в спам.
- **Что не делает.** Заявка нигде не сохраняется (ни в файле, ни в базе): если письмо не принято, посетитель видит ошибку и телефон офиса. В журнал не пишутся имя и телефон. Отменённый прототип формы (имя, контакт, пожелания) не восстанавливался.

## Изменения и деплой

Автоматического CI/CD нет, и связи GitHub → сервер нет. Публикация вручную, порядок такой:

1. **Сверка.** Перед правкой убедиться, что боевой сайт совпадает с `origin/main`. Сравнивать хэши после приведения окончаний строк к одному виду: в репозитории файлы с LF, а на Windows при `core.autocrlf=true` рабочая копия получается с CRLF (например, `tr -d '\r' < index.html | sha256sum`).
2. **Правка** в отдельной чистой рабочей копии (`git worktree`) от свежего `origin/main`. Основное дерево не трогать, если в нём есть незакоммиченные изменения.
3. **Проверка** на ширинах 320, 390, 768, 1024, 1440 px и на телефоне/десктопе для затронутых блоков; проверять то, что менялось, не «в целом».
4. **Commit и `git push origin HEAD:main`** без `--force`.
5. **Бэкап на сервере** до загрузки: копия текущего файла в каталоге вида `/root/backups/<название-правки>-pre-<UTC-время>/`, с проверкой хэша копии.
6. **Загрузка** только изменённых файлов по SSH-ключу (раздел «Доступ к серверу»; скрипт `deploy_index_key.py` сверяет сервер с базовым коммитом, делает бэкап, грузит и читает обратно). Загружать файл, полученный из `git show origin/main:<путь>` (в нём LF), а не CRLF-копию из рабочего дерева.
7. **Проверка результата:** хэш файла на сервере равен хэшу из `origin/main`; ключевые фразы и картинки на боевой странице отвечают 200; остальное содержимое не изменилось.

Правило для изображений: на сервере для `assets/images` действует долгий кеш (`Cache-Control: max-age=2592000`, 30 дней). Заменённый файл под тем же именем посетитель, уже открывавший сайт, не увидит. Поэтому при замене изображения всегда давайте новое имя (как у `award-*-v2.webp`) и меняйте ссылки в `index.html`; старый файл оставляйте на месте.
