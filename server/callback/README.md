# Сервис заявок: «Заказать звонок», «Напишите нам», «Круизы»

Серверная часть трёх форм kupit-tyr.ru (одно окно на странице, три режима, одно поле `topic`). Сайт остаётся статическим: форма отправляет `POST /api/callback`, nginx передаёт запрос сервису на `127.0.0.1:8731`, сервис проверяет поля и отправляет письмо менеджеру. Наружу сервис не слушает.

Это не часть деплоя `index.html`: файлы из этой папки на сервер сами не попадают, их ставят отдельно (см. «Установка»).

## Что делает сервис

- Принимает JSON `{topic, name, phone, message, consent, hp_field, elapsed}`, проверяет: имя 2–60 символов (только буквы, пробел, дефис, точка, апостроф), телефон 10–15 цифр (российские номера приводятся к `+7XXXXXXXXXX`), согласие `true`.
- Темы (`topic`, без него — `callback`, как у первой версии): `callback` — «Заказать звонок» (сообщения нет, поле игнорируется); `write` — «Напишите нам» (сообщение обязательно, 3–1500 символов); `cruise` — «Круизы» (сообщение необязательно, до 1500 символов; в теме и в первой строке письма явно «ИНТЕРЕС: КРУИЗЫ»). В сообщении убираются управляющие символы, больше двух ссылок отклоняются; неизвестная тема — 422. Темы письма: «Заказ звонка с сайта kupit-tyr.ru», «Напишите нам: сообщение с сайта kupit-tyr.ru», «Круизы: заявка с сайта kupit-tyr.ru».
- Защита: заголовок `Origin` (только `https://kupit-tyr.ru` и `https://www.kupit-tyr.ru`), `Content-Type: application/json`, тело до 7000 байт (1500 четырёхбайтных символов помещаются), скрытое поле `hp_field` (заполнено — запрос молча отбрасывается), проверка времени заполнения (быстрее 2 с — просьба повторить), 3 заявки с одного IP за 15 минут, 20 отклонённых запросов с IP за 15 минут, не больше 30 писем в час всего.
- Повторная отправка: точно такая же заявка (тема, телефон и текст сообщения) в течение 10 минут получает «успех», но второе письмо не уходит; другая тема или другое сообщение с того же телефона уходит как новая заявка; пока первое письмо отправляется, повтор получает 409. При сбое отправки слот освобождается, и посетитель может повторить сразу.
- Письмо уходит напрямую на MX получателя (`coralclub5av@mail.ru`, STARTTLS при наличии), без внешних сервисов и без сохранённых паролей. В лог пишутся только хеш IP (8 символов sha256), результат и ответ принявшего сервера (идентификатор очереди); имя и телефон не пишутся ни в лог, ни на диск.

## Файлы

| Файл | Назначение |
|---|---|
| `app.py` | сервис (`/opt/kupit-tyr-lead/app.py` на сервере) |
| `test_app.py` | тесты с поддельным SMTP на локальном порту: `python -m unittest server/callback/test_app.py -v` |
| `kupit-tyr-lead.service` | юнит systemd (без изменений относительно сервера) |
| `nginx-callback.location.conf` | блок `location = /api/callback` для HTTPS-сервера в `/etc/nginx/sites-available/kupit-tyr` |

## Установка и откат

Порядок: бэкап `app.py` и конфига nginx с проверкой sha256 → копия `app.py` → `systemctl restart kupit-tyr-lead` → вставка блока `location` перед `location / {` → `nginx -t` → `systemctl reload nginx` → проверка. Откат: вернуть оба файла из бэкапа, перезапустить сервис, `nginx -t`, перезагрузить nginx. Скрипты применения и отката 2026-10-05 лежат вне репозитория: `D:\POD_SOLNCEM\archive\callback-deploy-2026-10-05\`; пути бэкапов записаны в `BACKLOG.md`.

## Ограничения

- Письма отправляются без DKIM и без SPF-записи домена, у IP сервера нет PTR-записи; почтовые провайдеры вправе отнести такое письмо в спам или отклонить. Принятие письма сервером получателя (ответ 250) видно в логе, попадание в «Входящие» подтверждает только получатель.
- Антиспам-счётчики и защита от дублей хранятся в памяти: перезапуск сервиса их обнуляет.
- Заявка нигде не сохраняется. Если отправка не удалась, посетитель видит ошибку и телефон офиса, письмо не теряется «молча».
